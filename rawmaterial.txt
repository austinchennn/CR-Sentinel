AI解决

大模型完整读取整条请求参数的语义，无视空格、编码、注释拆分，直接识别底层意图：这段文本是用来操纵数据库/执行脚本，不管怎么伪装都能识别。

2. 无特征、新型0Day、自定义小众攻击（传统特征库完全无记录）

3. 跨多条请求、跨时间的链式入侵行为（传统单条日志判断不了）

老方案短板

传统IDS/WAF只能单条请求独立检测，没有跨日志关联分析能力。

老方案短板

AI解决

不靠访问频率数字，而是理解行为目的：持续遍历大量账号、反复尝试不同密码，判定为慢速暴力破解，不受访问次数阈值限制。

老方案短板

一、AI 能自动执行的防御操作（全部通过MCP调用CRDB完成）

1. 自动拉黑恶意IP（最核心阻断手段）

1）CRDB 建一张黑名单表
CREATE TABLE ip_blacklist (
  ip STRING PRIMARY KEY,
  risk_level STRING, -- high/mid/low
  block_until TIMESTAMP, -- 临时封禁时长
  attack_reason STRING,
  create_time TIMESTAMP DEFAULT now()
);
2）AI 判断高危攻击（延时注入、越权提权、慢速爆破）
通过 MCP run_read_query、run_write_query 执行插入SQL，把IP写入黑名单，设置封禁1天/永久封禁。
3）网站网关每次收到请求，先查这张黑名单，命中直接拒绝访问，黑客再也发不了请求。

2. 临时限流、限制接口访问权限（中度风险）

针对扫描器、低危爬虫，不直接拉黑，但限制访问频率：
单独一张 ip_rate_limit 表，AI写入限流规则，网关读取规则限制单IP每分钟请求次数，减缓扫描速度。

3. 作废被盗用/异常账号

AI识别账号异地登录、批量换密码、后台异常操作；
通过MCP更新用户表：锁定账号、强制下线、重置登录令牌，阻断黑客利用账号入侵后台。

4. 自动生成安全加固建议，同步存入任务队列

CRDB 事务队列表存储优化任务，后续定时执行：

• 发现频繁SQL注入 → 生成任务：给接口增加参数白名单

• 发现大量目录扫描 → 生成任务：隐藏后台管理路径
任务存入队列，开发/运维后台可以直接查看修复清单。

5. 高危告警推送（短信/邮件/企业消息）

AI判定严重入侵时，通过MCP写入告警表，另一个Lambda定时读取告警，推送通知，同步完成人工兜底。

三、为什么传统安全方案做不到这种全自动闭环

1. WAF只能拦截预设规则，无法自主决策动态拉黑
传统WAF规则是提前写死，不能根据实时日志、攻击上下文动态新增拉黑IP；想要拉黑，必须人工登录后台手动添加。

2. IDS/ELK只会告警，没有写入数据库执行防御的能力
老工具只有“输出日志、弹提醒”功能，不具备调用存储、修改黑名单、锁定账号的执行通道，发现攻击后必须人手动操作。

3. 无法结合完整业务上下文做分级处置
传统工具只会一刀切拦截，AI可以区分风险：

• 爬虫扫描 → 限流即可；

• 数据库拖库注入 → 立刻永久拉黑IP；

• 普通用户误操作 → 仅记录告警不处罚。
